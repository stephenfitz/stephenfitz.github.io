RED-BLACK TREES

  1. Every node is colored red or black.
  2. The root and all leaves (NILs) are black.
  3. No red node has a red parent.
  4. Every simple path from a node x to any descendant NIL has the same number of black nodes (black-height of x).

All four red-black properties satisfied.

RED-BLACK HEIGHT THEOREM

Theorem: A red-black tree with \(n\) keys has height \(h \le 2\lg(n+1)\).

Idea: Merge each red node into its black parent to form a 2–3–4 tree with uniform leaf depth.

  • Merge every red node into its black parent.
  • This creates a tree where each node has 2, 3, or 4 children — a 2–3–4 tree.
  • All leaves in this 2–3–4 tree have uniform depth $h'$.
  • Let $ h $ be the height of the red–black tree and $ h' $ be the height of the corresponding 2–3–4 tree.
  • Since at most half the nodes along any path are red, we have:

$$ h' \ge \frac{h}{2} $$

  • The number of leaves is $ n + 1 $.
  • For a 2–3–4 tree of height $ h' $, $ n + 1 \ge 2^{h'} $.

$$\Rightarrow \log_2(n + 1) \ge h' \ge \frac{h}{2}$$

$$\Rightarrow h \le 2 \log_2(n + 1)$$

RED-BLACK TREES: QUERY TIME

Corollary: SEARCH, MIN, MAX, SUCCESSOR, PREDECESSOR run in \(O(\log n)\).

TREE ROTATIONS

Rotations preserve in-order key order and run in \(O(1)\).

$$ a \in \alpha , b \in \beta , c \in \gamma \implies a \leq A \leq b \leq B \leq c $$

RB-INSERT: HIGH-LEVEL STRATEGY

  • Insert as in BST; color new node red
  • Only property 3 (no red parent of red node) may be violated
  • Fix-up proceeds up the tree using recoloring and at most two rotations

RB-INSERT(T, x):
  TREE-INSERT(T, x)
  color[x] ← RED
  while x ≠ root[T] and color[parent[x]] = RED:
    if parent[x] = left[parent[parent[x]]]:
      y ← right[parent[parent[x]]] # "uncle"
      if color[y] = RED: # case 1
        color[parent[x]] ← BLACK
        color[y] ← BLACK
        color[parent[parent[x]]] ← RED
        x ← parent[parent[x]]
    ...
                    

      else:
        if x = right[parent[x]]: # case 2 → 3
          x ← parent[x]
          LEFT-ROTATE(T, x)
        # case 3
        color[parent[x]] ← BLACK
        color[parent[parent[x]]] ← RED
        RIGHT-ROTATE(T, parent[parent[x]])
    else:
      # symmetric: swap 'left' and 'right'
      ...
  color[root[T]] ← BLACK

RB-INSERT: CASE 1 (RECOLOR)

Parent and uncle red ⇒ recolor and move violation up.

RB-INSERT: CASE 2 (ROTATE TO CASE 3)

Inner configuration ⇒ one rotation converts to case 3.

RB-INSERT: CASE 3 (ROTATE, RECOLOR)

Rotation and recoloring ⇒ done.

RB-INSERT ANALYSIS

  • Zero or more Case 1 recolor steps
  • At most two rotations (Case 2 then Case 3)
  • Time: \(O(\log n)\) with \(O(1)\) rotations

RB-DELETE has analogous asymptotics and bounded rotations.

SUMMARY

  • BSTs: simplicity with performance tied to height
  • Red-Black trees: enforce balance to guarantee \(O(\log n)\) operations
  • Rotations are the primitive for structural adjustments
