TASK SCHEDULING

  • Input: Activities \(a_1,\dots,a_n\) with start times \(s_i\) and finish times \(f_i\).
  • Constraint: Only one activity at a time; activities cannot overlap.
  • Goal: Maximize the number of activities completed today.

INTUITION

  • To leave room for future activities, prefer activities that finish earliest.
  • This greedy choice enables the largest residual window for subsequent selections.

GREEDY ALGORITHM

  • Sort activities by increasing finish time \(f_i\).
  • Select the first activity; then repeatedly add the next activity whose start time \(\ge\) last selected finish.

Input: A = [a1..an], starts S = [s1..sn], finishes F = [f1..fn]

Output: C = maximum-size set of non-overlapping activities

Sort activities by increasing F (break ties arbitrarily)
                    

C = [A[1]]
last = 1
for i = 2..n:
  if S[i] ≥ F[last]:
    append A[i] to C
    last = i
return C

WHY EARLIEST-FINISH GREEDY IS OPTIMAL

  • Define subproblem \(B[i,j]\): maximum #activities after activity \(i\) ends and before \(j\) starts.
  • Exchange argument: if an optimal solution picks an activity that finishes later than the greedy choice, swapping improves or preserves feasibility and never reduces the count.

OPTIMALITY SKETCH VIA EXCHANGE

  • Consider subproblem \(B[i, n+1]\); greedy picks \(a_k\) with earliest finish among feasible.
  • Take any optimal solution not containing \(a_k\); let \(a_j\) be its first activity.
  • Since \(f_k \le f_j\), replace \(a_j\) by \(a_k\); feasibility is preserved and remaining window is no smaller.
  • Inductively, greedy achieves an optimal-size set.

HUFFMAN ENCODING

ASCII encoding assigns 8 bits to each character. However some characters appear often (such as e).

character frequency distribution in English text

Fixed-width encodings (e.g., 8-bit ASCII) are wasteful when character frequencies are skewed.

Goal: assign shorter codewords to frequent symbols and longer ones to rare symbols to minimize expected length.

PREFIX-FREE PROPERTY

  • No codeword is a prefix of another.
  • Guarantees unique decodability via tree traversal from root to leaves.

this works!

as long as all letters are leaves the code is prefix-free

STRATEGY

greedily build subtrees, starting with the infrequent letters

  • Repeatedly merge the two least frequent nodes into a new parent with summed frequency.
  • Assign one child edge as 0 and the other as 1; codes are read from root to leaves.

Merge the two smallest frequencies \(5\) and \(9\) to form \(14\).

Merge the next two smallest \(12\) and \(13\) to form \(25\).

Merge \(14\) and \(16\) to form \(30\).

Merge \(25\) and \(30\) to form \(55\).

Merge \(55\) and \(45\) to obtain the root \(100\); read codewords from root to leaves.

EXPECTED CODE LENGTH

The expected bits per symbol is

\[ \mathbb{E}[L] \;=\; \sum_{c \in C} p(c)\,\ell(c), \]

where \(p(c)\) is the symbol probability and \(\ell(c)\) is its codeword length (tree depth).

expected cost of encoding a letter:

$$ 1*0.45 + \\ 3*0.41 + \\ 4*0.14 = \\ 2.24 $$ 


# C: symbols with frequencies
Q = PriorityQueue(C, key = freq)

while Q.size() > 1:
  x = Q.extract_min()
  y = Q.extract_min()
  z = new InternalNode()
  z.left = x; z.right = y
  z.freq = x.freq + y.freq
  Q.insert(z)

root = Q.extract_min()
return root

DECODING

  • Start at root; read bits left (0) / right (1) until a leaf is reached.
  • Emit the leaf symbol; restart from root for the next symbol.
  • Prefix-free property ensures unambiguous parsing without separators.
