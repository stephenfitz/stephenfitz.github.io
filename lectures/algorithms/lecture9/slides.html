TREES

Trees were designed to model hierarchical structure and recursive decompositions.

  • Node (root, parent, child, leaf)
  • Edge
  • Subtree
  • Height/Depth: longest path length to a leaf
  • Families: Binary, Ternary, …, N-ary
  • Full: each node has none or all children
  • Complete: all levels full except possibly last (filled left-to-right)
  • Perfect: all internal nodes have all children; all leaves at same level
  • Balanced: height difference of children ≤ 1 at every node

HEAPS

Heaps efficiently implement priority queues using complete binary trees.

QUEUE ADT

  • dynamic set of elements
  • operations: MakeNewQ(), Enqueue(x), Dequeue()
  • classic implementations: array, linked list; Θ(1) operations

PRIORITY QUEUE ADT

  • dynamic set of (key, data) pairs
  • Insert(x), Extract-Max (or Extract-Min)
  • use cases: schedule the highest-priority job

HEAP: STRUCTURE

  • conceptually: binary tree; nearly complete
  • in memory: compact array representation
  • bottom level filled left-to-right
  • For height \(h\): \(N_{\min}(h)=2^{h}\), \(N_{\max}(h)=2^{h+1}-1\).
  • For \(n\) nodes: \(h=\lfloor \log_2 n \rfloor\) so \(2^{h} \le n \le 2^{h+1}-1\).
  • Leaves in array layout (1-based): indices \(\lfloor n/2 \rfloor+1,\dots,n\).

HEAP PROPERTY (MAX-HEAP)

  • For every parent/child: parent.key ≥ child.key
  • Maximum is at the root; keys non-increasing along any path

Root holds the maximum key; each subtree is itself a max-heap.

ARRAY REPRESENTATION

  • Store nodes level-order, left-to-right
  • Indexing (1-based): Left(i)=2i, Right(i)=2i+1, Parent(i)=⌊i/2⌋
  • Example array: [16, 14, 10, 8, 7, 9, 3, 2, 4, 1]

Constant-time navigation via index arithmetic.

CHECK YOUR UNDERSTANDING

  • Is [20, 10, 4, 9, 6, 3, 2, 8, 7, 5, 12, 1] a valid max-heap? If not, repair.
  • No. Violation: child 12 > parent 6 at indices 11 and 5. Repair via heapify-up from index 11 ⇒ array becomes [20, 12, 4, 9, 10, 3, 2, 8, 7, 5, 6, 1].
  • Is a decreasingly sorted array a valid max-heap?
  • Yes. Any strictly decreasing array A[1..n] is a valid max-heap because for every parent i, its children are at positions 2i and 2i+1 > i, hence A[i] ≥ A[2i], A[2i+1].

LOCAL REPAIR: HEAPIFY DOWN

After decreasing a node’s key (or moving last element to root), push it down until heap property holds.

  • Swap with largest child while smaller than a child
  • Stops when ≥ both children or at a leaf

This is operation is often called "max heapify" or "heapify down".


MAX-HEAPIFY(A, i, heap_size)
  L ← 2i
  R ← 2i+1
  largest ← i
  if L ≤ heap_size and A[L] > A[largest] then 
    largest ← L
  if R ≤ heap_size and A[R] > A[largest] then 
    largest ← R
  if largest ≠ i then
    swap A[i], A[largest]
    MAX-HEAPIFY(A, largest, heap_size)

Running time: O(log n)

What does MAX-HEAPIFY do on input:

[2.5, 10, 4, 9, 6, 3, 2, 8, 7, 5, 0, 1]

Answer: MAX-HEAPIFY at i=1 swaps 2.5↔10, then 2.5↔9, then 2.5↔8; stop. Result: [10, 9, 4, 8, 6, 3, 2, 2.5, 7, 5, 0, 1].

EXTRACT-MAX

Remove and return the maximum while maintaining a max-heap.

  • swap root with last element
  • pop last element and shrink size by 1
  • heapify down from root

EXTRACT-MAX(A, heap_size)
  if heap_size < 1 then error "underflow"
  max ← A[1]
  A[1] ← A[heap_size]
  heap_size ← heap_size − 1
  MAX-HEAPIFY(A, 1, heap_size)
  return max

LOCAL REPAIR: HEAPIFY UP

After increasing a node’s key, bubble it up until heap property holds.

  • While A[i] > A[parent(i)], swap with parent

What does Heapify Up at i=10 do on:

[20, 10, 4, 9, 6, 3, 2, 8, 7, 21, 0, 1]

Answer: HEAPIFY-UP from i=10 swaps 21↔6, then 21↔10, then 21↔20; stop. Result: [21, 20, 4, 9, 10, 3, 2, 8, 7, 6, 0, 1].


HEAPIFY-UP(A, i)
  while i > 1 and A[⌊i/2⌋] < A[i] do
    swap A[i], A[⌊i/2⌋]
    i ← ⌊i/2⌋

Running time: O(log n)


HEAP-INCREASE-KEY(A, i, key)
  if key < A[i] then error "new key is smaller"
  A[i] ← key
  while i > 1 and A[⌊i/2⌋] < A[i] do
    swap A[i], A[⌊i/2⌋]
    i ← ⌊i/2⌋

INSERT INTO MAX-HEAP

  • Append new element at end; increase heap size
  • Heapify up from the new position

MAX-HEAP-INSERT(A, x, heap_size)
  heap_size ← heap_size + 1
  A[heap_size] ← x
  HEAPIFY-UP(A, heap_size)

BUILD A HEAP

Transform an arbitrary array A[1..n] into a max-heap by local repairs.

  • Call MAX-HEAPIFY on internal nodes from ⌊n/2⌋ down to 1
  • Reason: A[⌊n/2⌋+1..n] are leaves
  • Running time: O(n log n)

BUILD-MAX-HEAP(A, n)
  heap_size ← n
  for i ← ⌊n/2⌋ downto 1 do
    MAX-HEAPIFY(A, i, heap_size)

HEAP SORT

  • max element at root (A[1])
  • move it to end by swapping with A[n] and shrink size
  • restore heap on remaining elements; repeat

HEAPSORT(A, n)
  BUILD-MAX-HEAP(A, n)
  for i ← n downto 2 do
    swap A[1], A[i]
    heap_size ← heap_size − 1
    MAX-HEAPIFY(A, 1, heap_size)
