lecture #13

KNAPSACK PROBLEM

0/1 KNAPSACK

Input: \(n\) items, weights \(w[i]\), benefits \(b[i]\), capacity \(W\). Choose a subset \(T\subseteq \{1..n\}\) to maximize \(\sum_{i\in T} b[i]\) subject to \(\sum_{i\in T} w[i] \le W\).

0/1 means each item is either taken or not taken; no fractional items.

BRUTE FORCE BASELINE

Enumerate all \(2^n\) subsets; select the feasible one with maximum benefit. Exponential time \(O(2^n)\), not acceptable for large \(n\).

CHOOSING SUBPROBLEMS

Naïve “first \(k\) items” alone is insufficient. Proper subproblem includes remaining capacity: let \(B[k,w]\) be the maximum value using items \(1..k\) with available capacity \(w\).

RECURRENCE

\[ B[k,w] = \begin{cases} B[k{-}1,w], & \text{if } w[k] > w,\\ \max\{B[k{-}1,w],\; B[k{-}1,\,w{-}w[k]] + b[k]\}, & \text{otherwise.} \end{cases} \]

Choice: exclude item \(k\) or include it (if it fits) and add \(b[k]\) plus the best for reduced capacity.


Knapsack_BottomUp(w[1..n], b[1..n], W):
  create B[0..n][0..W]
  for cap in 0..W: B[0][cap] = 0
  for i in 1..n:
    for cap in 0..W:
      if w[i] <= cap:
        B[i][cap] = max(B[i-1][cap],
                    b[i] + B[i-1][cap - w[i]])
      else:
        B[i][cap] = B[i-1][cap]
  return B[n][W]

EXERCISE

Items: weights [2,3,4,5], benefits [3,4,5,6], capacity \(W=5\).

Use the recurrence to fill the table; the optimum is recovered at \(B[4,5]\).

TRACEBACK


Knapsack_Traceback(B, w[1..n], b[1..n], W):
  i = n; cap = W; T = empty set
  while i > 0 and cap >= 0:
    if B[i][cap] == B[i-1][cap]:
      i = i - 1  // item i not taken
    else:
      add i to T
      cap = cap - w[i]
      i = i - 1
  return T

COMPLEXITY

Knapsack bottom-up time runs in \(\Theta(nW)\). Space can be reduced to \(O(W)\) for when only the final value is needed.

FRACTIONAL KNAPSACK

  • items \(i=1,\dots,n\) with weight \(w[i]\) and benefit \(b[i]\)
  • knapsack capacity \(W\)
  • maximize total benefit subject to total weight \(\le W\)
  • fractional setting: can take any portion of an item

FRACTIONAL VS. 0/1 KNAPSACK

  • 0/1: each item either fully taken or not taken at all
  • fractional: arbitrary fractions allowed
  • greedy approach is optimal for fractional; not generally optimal for 0/1

GREEDY STRATEGY

  • Compute unit benefit \(R[i] = b[i]/w[i]\)
  • Sort items by decreasing \(R[i]\)
  • Take as much as possible of the current best item until capacity is filled

ALGORITHM

  • Precompute ratios \(R[i]\)
  • Sort by \(R[i]\) descending
  • Iterate through items; take whole item if it fits, otherwise take the fraction that fills remaining capacity
  • Return total benefit

# Input: weights w[1..n], benefits b[1..n], capacity W

# Output: maximum achievable benefit B

for i = 1 to n:
  R[i] = b[i] / w[i]

sort items so that R[1] ≥ R[2] ≥ ... ≥ R[n]
                        

i = 1
B = 0

while W > 0 and i ≤ n:
  if w[i] ≤ W:
    B = B + b[i]
    W = W - w[i]
  else:
    B = B + R[i] * W
    W = 0
  i = i + 1

return B

COMPLEXITY

  • Compute ratios: \(O(n)\)
  • Sort by ratio: \(O(n \log n)\)
  • Single pass select/fractional fill: \(O(n)\)
  • Overall: \(O(n \log n)\)

WHY GREEDY IS OPTIMAL (FRACTIONAL)

Exchange argument / proof by contradiction:

  • If an optimal solution uses a lower-ratio item where a higher-ratio item is available, swapping an equal weight increases value
  • Therefore an optimal solution can be transformed to the greedy solution without loss

PROOF SKETCH (CONTRADICTION)

  • Assume greedy solution \(G\) is not optimal; let \(OPT\) have strictly higher value
  • There exist items \(i\) (in \(G\)) and \(j\) (in \(OPT\)) with \(R_i > R_j\)
  • Shift weight \(x\) from \(j\) to \(i\): value increases by \(x(R_i - R_j) > 0\)
  • Contradiction: \(G\) was optimal

WHY GREEDY FAILS FOR 0/1 KNAPSACK

  • Taking the best ratio early can block capacity for a better combination
  • Local choice does not account for future packing constraints
