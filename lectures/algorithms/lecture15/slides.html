BINARY SEARCH TREES

  • Binary tree: each node has 0, 1, or 2 children
  • BST property: for any node x,
    \(\forall y \in \text{left}(x):\; \mathrm{key}(y) \le \mathrm{key}(x)\)
    \(\forall y \in \text{right}(x):\; \mathrm{key}(y) \ge \mathrm{key}(x)\)

BST DATA STRUCTURE

  • Each node stores: key, left, right, parent
  • Key type supports total ordering (e.g., numbers, strings)

Keeping vertical alignment clarifies in-order positions; unique legal insertion point for key 4 is clear.

BST HEIGHT

  • Best case: \(h = \Theta(\log n)\) (well-balanced)
  • Worst case: \(h = \Theta(n)\) (degenerate chain)

Tree shape governs performance of all basic operations.

BST SEARCH

Follows left/right pointers based on key comparisons.

Running time: \(\Theta(\text{height})\)


TREE-SEARCH(x, k)
  if x == NIL or k == x.key
      return x
  if k < x.key
      return TREE-SEARCH(x.left, k)
  else
      return TREE-SEARCH(x.right, k)

Initial call: TREE-SEARCH(T.root, k)

BST INSERTION

  • Search down to a NIL child, remembering the parent
  • Attach new node as left or right child

Running time: \(\Theta(\text{height})\)


TREE-INSERT(T, z)
  y = NIL
  x = T.root
  while x ≠ NIL
      y = x
      if z.key < x.key
          x = x.left
      else
          x = x.right
  z.p = y
  if y == NIL
      T.root = z // tree T was empty
  elseif z.key < y.key
      y.left = z
  else
      y.right = z

TREE MINIMUM AND MAXIMUM

  • \(\mathrm{Tree\text{-}Min}(x)\): follow left pointers
  • \(\mathrm{Tree\text{-}Max}(x)\): follow right pointers

Running time: \(\Theta(\text{height})\)


TREE-MINIMUM(x)
  while x.left ≠ NIL
      x = x.left
  return x

TREE-MAXIMUM(x)
  while x.right ≠ NIL
      x = x.right
  return x

TREE SUCCESSOR

  • If node has right subtree: min of right subtree
  • Else: go up via parent pointers to first ancestor for which node lies in left subtree

Running time: \(\Theta(\text{height})\)


TREE-SUCCESSOR(x)
  if x.right ≠ NIL
      return TREE-MINIMUM(x.right)
  y = x.p
  while y ≠ NIL and x == y.right
      x = y
      y = y.p
  return y

TREE TRAVERSALS

  • Inorder: Left → Root → Right (sorted order in BSTs)
  • Preorder: Root → Left → Right (copying structure)
  • Postorder: Left → Right → Root (aggregate properties like height or number of nodes)

Algorithm Inorder-Tree-Walk(x):
  if x ≠ NIL:
    Inorder-Tree-Walk(x.left)
    print x.key
    Inorder-Tree-Walk(x.right)

Initial call: Inorder-Tree-Walk(T.root) | Running time: Θ(n)


Algorithm Copy-Tree(x):
  if x == NIL: return NIL
  y ← new node
  y.key ← x.key
  y.left  ← Copy-Tree(x.left)
  y.right ← Copy-Tree(x.right)
  return y

Initial call: Copy-Tree(T.root) | Running time: Θ(n)


Algorithm Find-height(x):
  if x == NIL: return -1
  h1 ← Find-height(x.left)
  h2 ← Find-height(x.right)
  return max(h1, h2) + 1

Initial call: Find-height(T.root) | Running time: Θ(n)

BST VS. QUICKSORT: COMPARISON

  • First inserted key (root) compared with all subsequent keys
  • Within each subtree, first inserted key compared within that subtree
  • Analogy: root behaves like quicksort pivot
  • Random insertion order ⇒ expected total comparisons \(O(n \log n)\)

AVERAGE NODE DEPTH

Depth of a node equals number of comparisons during its insertion.

Summing over nodes gives total comparisons; averaging yields expected depth on random permutations.

BST NODE DEPTH ↔ COMPARISONS

  • Depth of a node = # edges from root to that node.
  • When inserting a key, its depth equals the # of comparisons made during that insertion.
  • Example: compared with 10 → 4 → 6 → placed ⇒ depth = 3.

TOTAL & AVERAGE DEPTH

  • Sum of all node depths = total # of comparisons over all insertions.
  • Average node depth = (1/n) × (total # of comparisons).

EXPECTED COSTS (RANDOM INSERTION ORDER)

  • Assume all input permutations are equally likely.
  • Insertion-comparison structure matches randomized quicksort’s partitioning recurrences.
  • Therefore, expected total comparisons = O(n log n).

AVERAGE DEPTH RESULT

Average depth = (1/n) · E[total comparisons] = (1/n) · O(n log n) = O(log n).

INTUITION

  • Randomly built BSTs are balanced in expectation; most nodes sit ≈ log n levels from the root.
  • But worst case (e.g., sorted input) yields depth O(n).
