INSERTION SORT

The Problem of Sorting

We are given a sequence of numbers and our goal is to rearrange them into a sorted order.

Formal Definition

  • Input: A sequence of n numbers <a1, a2, ..., an>.
  • Output: A permutation (reordering) <a'1, a'2, ..., a'n> of the input sequence such that a'1 ≤ a'2 ≤ ... ≤ a'n.

Sorting Example

Input:

8 2 4 9 3 6
Output: 
2 3 4 6 8 9

Insertion Sort

Insertion sort is simple algorithm for sorting a small number of elements (or a sequence that is nearly sorted).

It works the way many people sort a hand of playing cards. We start with an empty left hand and the cards face down on the table. We then remove one card at a time from the table and insert it into the correct position in the left hand.

Insertion Sort: The Algorithm

The algorithm iterates from the second element (j=2) to the end of the array. In each iteration, it takes the current element (the "key") and finds its correct place within the already sorted part of the array (A[1...j-1]).

First, we set up the main loop and store the current value as `key`.


                    for j <- 2 to n do
                        key <- A[j];
                        i <- j - 1;

Next, we shift elements greater than `key` one position to the right and insert the `key`.


                    for j <- 2 to n do
                        key <- A[j];
                        i <- j - 1;
                        while i > 0 and A[i] > key do
                            A[i+1] <- A[i];
                            i <- i - 1;
                        end
                        A[i+1] <- key;
                    end

Example of Insertion Sort

Let's trace the algorithm on an example input array.

Initial Array

Here is the unsorted input sequence.

8 2 4 9 3 6

j = 2

The key is 2. We compare it with 8, shift 8 to the right, and insert 2.

2 8 4 9 3 6

j = 3

The key is 4. We compare it with 8, shift 8, and insert 4 before it.

2 4 8 9 3 6

j = 4

The key is 9. It's already in the correct position relative to the sorted subarray.

2 4 8 9 3 6

j = 5

The key is 3. We shift 9, 8, and 4 to the right before inserting 3.

2 3 4 8 9 6

j = 6

The key is 6. We shift 9 and 8 to the right, then insert 6.

2 3 4 6 8 9

Done!

The final array is now sorted.

2 3 4 6 8 9

Correctness of Algorithms

How do we know for sure that an algorithm produces the correct result for every possible input?

A basic tool for this is mathematical induction.

Proving Correctness

We look for an iterative structure and identify "invariants" — properties that remain true at particular steps of the algorithm. We use induction to show that these guarantees hold.

The Inductive Proof Framework

To analyze iterative algorithms, we usually prove three statements about a loop invariant:

  • Initialization (Base Case): The invariant is true before the first loop iteration.
  • Maintenance (Inductive Step): If the invariant is true before an iteration, it remains true after the iteration.
  • Termination: When the loop terminates, the invariant gives us a useful property that helps show the algorithm is correct.

Correctness of Insertion Sort

Let's apply this framework to prove that Insertion Sort is correct.

Loop Invariant for Insertion Sort

Loop Invariant: At the start of each iteration of the `for` loop (indexed by `j`), the subarray A[1...j-1] consists of the elements originally in A[1...j-1], but in sorted order.

The Proof

  • Initialization: Before the first loop (j=2), the subarray A[1...1] is trivially sorted. The invariant holds.
  • Maintenance: In each iteration `j`, the inner `while` loop finds the correct position for A[j] within the already sorted A[1...j-1]. The elements are shifted, and A[j] is inserted. The resulting subarray A[1...j] is now sorted.
  • Termination: The `for` loop terminates when j becomes n+1. At this point, the invariant holds for j=n+1. This means the subarray A[1...n] is sorted, which is the entire array.

Thus, Insertion Sort is correct.

Analyzing Running Time

Correctness isn't everything. For an algorithm to be useful, it must also be efficient.

Other important qualities include:

  • Time and space efficiency
  • Modularity
  • Robustness
  • Simplicity

Measuring Running Time

Our typical goal is to find the most time- and space-efficient algorithm for a problem.

  • We parameterize the running time, T(n), by the size of the input, `n`.
  • The running time depends on the specific input. An already sorted sequence is easier to sort.
  • Because of this, we generally seek upper bounds on the running time.

Kinds of Analyses

  • Worst-case: (Usually)
    T(n) is the maximum time the algorithm takes on any input of size n. This is a guarantee.
  • Average-case: (Sometimes)
    T(n) is the expected time over all inputs of size n. This requires assumptions about the statistical distribution of the inputs.
  • Best-case: (Rarely)
    Analyzing performance on one specific, easy input isn't very meaningful.

Asymptotic Analysis

The exact running time depends on the speed of the computer.

The Big Idea:

  • Ignore machine-dependent constants (like CPU speed).
  • Look at the growth of T(n) as the input size `n` becomes very large (n → ∞).

Running Time of Insertion Sort

The running time depends on the number of comparisons and swaps.

In the worst-case scenario (e.g., an array sorted in reverse order), every element A[j] must be compared with every element in the entire sorted subarray A[1...j-1].

  • Outer loop: $j=2,\dots,n$ → $n-1$ iterations
  • Per-iteration worst-case shifts: up to $j-1$

Cost constants:

  • $c_1$: outer-iteration overhead
  • $c_2$: comparison
  • $c_3$: move (shift/write)

$$T_{\text{worst}}(n)=c_1(n-1)+c_2\sum_{j=2}^{n} j+c_3\sum_{j=2}^{n}(j-1)$$

$$\sum_{j=2}^{n} j=\tfrac{n(n+1)}{2}-1,\quad \sum_{j=2}^{n}(j-1)=\tfrac{n(n-1)}{2}$$

$$T_{\text{worst}}(n)=c_1(n-1)+c_2\Big(\tfrac{n(n+1)}{2}-1\Big)+c_3\tfrac{n(n-1)}{2}$$

$T_{\text{worst}}(n) = \tfrac{c_2+c_3}{2}\,n^2 + \Big(c_1+\tfrac{c_2}{2}-\tfrac{c_3}{2}\Big)n - (c_1+c_2)$

Best Case (already sorted)

Inner while does one comparison, no moves:

$$T_{\text{best}}(n)=c_1(n-1)+c_2(n-1)$$

Average Case (uniform random)

Expected shifts per iteration: $\tfrac{j-1}{2}$

$$\mathbb{E}[T(n)]=c_1(n-1)+c_2\sum_{j=2}^{n}\Big(\tfrac{j-1}{2}+1\Big)+c_3\sum_{j=2}^{n}\tfrac{j-1}{2}$$

$$=c_1(n-1)+\frac{c_2+c_3}{2}\sum_{j=2}^{n}(j-1)+c_2(n-1)$$

$$\mathbb{E}[T(n)]=\big(c_1+c_2\big)(n-1)+\tfrac{(c_2+c_3)}{4}\,n(n-1)$$

Takeaways

  • Worst: $\tfrac{(c_2+c_3)}{2}n^2 + O(n) \longrightarrow O(n^2)$
  • Average: $\tfrac{(c_2+c_3)}{4}n^2 + O(n) \longrightarrow O(n^2)$
  • Best: $(c_1+c_2)(n-1) \longrightarrow O(n)$

Is Insertion Sort Fast?

  • Moderately so, for small input sizes `n`.
  • Not at all, for large input sizes `n`. A quadratic running time becomes very slow as `n` grows.

Pipeline of Algorithm Design

This course will follow a general process for tackling algorithmic problems:

  1. Understand the problem, identify input/output, and design pseudocode.
  2. Prove the algorithm is correct, using techniques like loop invariants.
  3. Analyze the algorithm's time and space complexity to ensure efficiency.

MERGE SORT

Let's consider a variation on the sorting problem.

What if you are given two already sorted arrays to begin with, instead of one unsorted array?

MERGING TWO SORTED ARRAYS

The core operation in Merge Sort is merging two sorted subarrays.

You can efficiently merge them into one larger sorted array by repeatedly taking the smaller element from each array and adding it to the merged output.

Merge Sort is a "Divide and Conquer" algorithm.

  1. Divide: Split the n-element sequence to be sorted into two subsequences of n/2 elements each.
  2. Conquer: Sort the two subsequences recursively using merge sort.
  3. Combine: Merge the two sorted subsequences to produce the sorted answer.

The main function recursively splits the array until it gets to subarrays of size 1 (the base case), then merges them back together.


                        _________________mergesort________________________
                        MERGE-SORT(A, p, r)

                          if p >= r // length 0 or 1
                            return  // already sorted

                            q = floor((p + r) / 2) // midpoint

                            MERGE-SORT(A, p, q) // sort A[p:q]
                            MERGE-SORT(A, q + 1, r) // sort A[q+1:r]
                            MERGE(A, p, q, r) // merge them

The MERGE procedure is where the main work happens. We'll break it down into a few parts.

It takes the array A and the indices defining the two sorted subarrays, A[p:q] and A[q+1:r], and merges them in place.

First, calculate the lengths and create temporary arrays, L and R, to hold the two halves.


                    _________________merge____________________________
                    nL = q - p + 1  // length of A[p:q]
                    nR = r - q      // length of A[q+1:r]
                    let L[0:nL-1] and R[0:nR-1] be new arrays

Next, copy the data from the main array into the temporary L and R arrays.


                        _________________merge____________________________
                        for i = 0 to nL - 1
                          L[i] = A[p+i]

                        for j = 0 to nR - 1
                          R[j] = A[q+j+1]

Now, walk through L and R, repeatedly picking the smaller element and placing it back into the original array A.


                    _________________merge____________________________
                    i = 0, j = 0, k = p
                    while i < nL and j < nR
                      if L[i] <= R[j]
                        A[k] = L[i]
                        i = i + 1
                      else
                        A[k] = R[j]
                        j = j + 1
                      k = k + 1

After the main loop finishes, one of the temporary arrays might still have elements left. Copy them over.


                        _________________merge____________________________
                        // Copy the rest of L, if any
                        while i < nL
                        A[k] = L[i]
                        i = i + 1
                        k = k + 1

                        // Copy the rest of R, if any
                        while j < nR
                        A[k] = R[j]
                        j = j + 1
                        k = k + 1

Correctness of Merge Sort

We can prove Merge Sort is correct using induction on the size of the input subarray, n.

  • Base Case: If n=1, the subarray has one element and is trivially sorted. Merge Sort works correctly.
  • Inductive Step: Assume Merge Sort works for inputs smaller than n. For an input of size n, it recursively sorts two smaller subarrays. Since our assumption holds, they are sorted correctly. The MERGE procedure then correctly combines them. Thus, it works for size n.

Asymptotic Analysis: Θ-notation

To analyze efficiency, we use asymptotic notation to describe the growth rate of functions.

  • Definition: A function f(n) is in Θ(g(n)) if it's "sandwiched" between c1g(n) and c2g(n) for large n.
  • Heuristic: Drop low-order terms and ignore leading constants.
  • Example: 3n³ + 90n² - 5n + 6046 = Θ(n³).

Analyzing Merge Sort's Running Time

We can write a recurrence relation for the running time, T(n):

$T(n) = \begin{cases} \Theta(1) & \text{if } n=1 \\ 2T(n/2) + \Theta(n) & \text{if } n>1 \end{cases}$

  • Θ(1): The constant time for the base case.
  • 2T(n/2): The time for two recursive calls on problems half the size.
  • Θ(n): The time to merge the n elements.

Recursion Trees

We can visualize solving $T(n) = 2T(n/2) + cn$ with a recursion tree.

By expanding the tree, we can sum the cost at each level to find the total running time.

Merge Sort vs. Insertion Sort

  • The running time Θ(n lg n) grows more slowly than Insertion Sort's worst-case Θ(n²).
  • This means Merge Sort is asymptotically better and will always beat Insertion Sort for large enough inputs.
  • In practice, this crossover point is often around n=30.
  • Insertion Sort outperforms Merge Sort on inputs that are already nearly sorted!
