SOLUTION 1

Merge-Sort operates by repeatedly splitting the array into two halves, sorting each half, and then merging the two sorted halves:

  • Divide: Recursively split A into two subarrays of (almost) equal size.
  • Conquer: Recursively sort each subarray.
  • Combine: Merge the two sorted subarrays into a single sorted array.

The recursion tree for Merge-Sort on 8 elements has the following structure:

  • Level 0: One node for the full array of length 8.
  • Level 1: Two nodes, each corresponding to a subarray of length 4.
  • Level 2: Four nodes, each corresponding to a subarray of length 2.
  • Level 3: Eight leaf nodes, each a single element.

Each internal node represents a Merge-Sort call on a subarray, and each leaf represents a subarray of length 1 (already sorted).

Memoization speeds up recursive algorithms when the same subproblems are solved multiple times, as in typical dynamic programming examples:

  • Fibonacci numbers.
  • Longest common subsequence.
  • Other problems where the same state is recomputed many times.

In these settings, caching results of subproblems avoids repeated work.

In Merge-Sort:

  • Each recursive call sorts a unique subarray defined by a distinct index interval.
  • No subarray is sorted more than once.
  • There are no overlapping subproblems in the sense required for dynamic programming.

Therefore, memoization cannot reuse any work and offers no performance improvement for Merge-Sort.

SOLUTION 2

We define a DP formulation to avoid recomputing subproblems:

  • Let R[i] be the maximum revenue obtainable from a rod of length i.
  • Base case: R[0] = 0 (a rod of length 0 yields no revenue).
  • For each i from 1 to n, consider all possible first cuts of length j, where 1 ≤ j ≤ i.

The recurrence is:

\[ R[i] = \max_{1 \le j \le i} \bigl(P[j] + R[i - j]\bigr). \]

We fill a table R[0..n] bottom-up and return R[n].

  • P[j] is the price of a piece of length j.
  • R[i − j] is the maximum revenue for the remaining length i − j.
  • For each i, we try all j from 1 to i and take the best combination.

By storing all R[i] values in a table, we avoid recomputing subproblems and obtain a polynomial-time solution.


1: function RodCutting(P, n)
2:   Initialize R[0] ← 0
3:   for i ← 1 to n do
4:     R[i] ← 0
5:     for j ← 1 to i do
6:       R[i] ← max(R[i], P[j] + R[i − j])
7:     end for
8:   end for
9:   return R[n]
10: end function
  • The outer loop (over i) runs n times for lengths 1 through n.
  • The inner loop (over j) runs i times for each i.

Total number of iterations:

\[ 1 + 2 + 3 + \dots + n = \frac{n(n+1)}{2}. \]

Therefore the overall time complexity is \(\Theta(n^2)\), i.e. \(O(n^2)\).

SOLUTION 3

Key idea: scan through A while maintaining two quantities:

  • currentSum: maximum sum of a subarray ending at the current index.
  • maxSum: maximum subarray sum seen so far over all indices.

At each position i (i ≥ 1), we decide whether to:

  • Extend the previous subarray: currentSum + A[i].
  • Start a new subarray at i: A[i].

We then update maxSum to be the maximum of itself and currentSum.


1: Initialize currentSum ← A[0]
2: Initialize maxSum ← A[0]
3: for i ← 1 to n − 1 do
4:   currentSum ← max(A[i], currentSum + A[i])
5:   maxSum ← max(maxSum, currentSum)
6: end for
7: return maxSum
  • The algorithm makes a single pass over the array (from i = 1 to n − 1).
  • Each step performs a constant amount of work (a few comparisons and additions).

Therefore the overall running time is \(\Theta(n)\), i.e. \(O(n)\), where n is the size of the array.

EXTRA SOLUTION

Suppose the original input is stored in an array A of characters.

For every pair of indices i and j with i < j, define:

  • fi,j to be the length of the longest palindromic subsequence within the subarray A[i, …, j].

We will build an n × n table T, where n = length(A):

  • T[i][j] stores the length of the longest palindromic subsequence within A[i, …, j].

Then the length of a longest palindromic subsequence of the entire string A[0, …, n − 1] is T[0][n − 1].

We initialize T as follows:

  • For every i with 0 ≤ i ≤ n − 1:
    • T[i][i] = 1, since any single character is a palindrome of length 1.
  • For every pair (i, j) with 0 ≤ j < i < n:
    • T[i][j] = 0, since A[i, …, j] is the empty subarray.

These base cases anchor the dynamic programming table.

For indices i, j satisfying 0 ≤ i < j < n, we use the following recurrence:

\[ T[i][j] = \begin{cases} 2 + T[i+1][j-1], & \text{if } A[i] = A[j], \\ \max\bigl(T[i][j-1], T[i+1][j]\bigr), & \text{if } A[i] \ne A[j]. \end{cases} \]

Intuition:

  • If A[i] = A[j], we can extend any longest palindromic subsequence inside A[i+1, …, j−1] by placing A[i] at both ends.
  • If A[i] ≠ A[j], then any LPS in A[i, …, j] must either skip A[i] or skip A[j], hence we take the maximum of the two possibilities.

Case A[i] = A[j]:

  • We consider a longest palindromic subsequence of the inner substring A[i+1, …, j−1].
  • By putting A[i] in front and A[j] at the end, we obtain a longer palindrome by adding 2 characters.
  • Thus T[i][j] = 2 + T[i+1][j−1].

Case A[i] ≠ A[j]:

  • We either use A[i] (and drop A[j]) or use A[j] (and drop A[i]).
  • The best length is max(T[i][j−1], T[i+1][j]).

We fill the table T in increasing order of the length of the subarray (j − i):

  • Subarrays of length 1 (j = i): already initialized to 1.
  • Subarrays of length 2, then 3, and so on, up to length n.

This is typically implemented by iterating over the distance d = j − i from 1 to n − 1, and for each d iterating over all valid i.


FindMaxLLP(A):
1: Let n = length(A)
2: Initialize T to be an empty n × n array
3: for i ← 0 to n − 1 do
4:   for j ← 0 to n − 1 do
5:     if j > i then
6:       T[i][j] ← 0
7:     end if
8:     if i = j then
9:       T[i][j] ← 1
10:    end if
11:  end for
12: end for


13: for d ← 1 to n − 1 do
14:   for i ← 0 to n − d − 1 do
15:     j ← i + d
16:     if A[i] = A[j] then
17:       T[i][j] ← 2 + T[i + 1][j − 1]
18:     else
19:       T[i][j] ← max(T[i][j − 1], T[i + 1][j])
20:     end if
21:   end for
22: end for
23: return T
  • The table T has n × n entries.
  • Initialization loops visit each entry at most once or twice and perform constant-time work per entry.
  • The nested loops over d and i also visit each (i, j) pair a constant number of times and perform constant-time updates using the recurrence.

Therefore the running time of FindMaxLLP is \(\Theta(n^2)\), i.e. \(O(n^2)\).
