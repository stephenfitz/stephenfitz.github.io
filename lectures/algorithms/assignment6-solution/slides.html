SOLUTION 1

Greedy idea:

  • Sort all jobs by their profit in descending order.
  • For each job in that order, schedule it in the latest available time slot on or before its deadline.
  • This maximizes total profit while keeping earlier slots free for other jobs, increasing flexibility.

1: Let J ← list of job indices 1 to n
2: Sort J in descending order of p[i]
3: Let D ← max(d[1..n])
4: Initialize slot[1..D] as false
5: for each job index j in J do
6:     for t ← d[j] to 1 do
7:         if slot[t] = false then
8:             slot[t] ← true
9:             Add j to s
10:             break
11:         end if
12:     end for
13: end for
14: return s
  • Sorting jobs by profit: \(O(n \log n)\)
  • Assigning time slots for each job: \(O(n \cdot d_{\max})\), where \(d_{\max}\) is the maximum deadline
  • Total running time: \(O(n \cdot d_{\max}) + O(n \log n)\)

SOLUTION 2

Key Observations

  • If the total gas is less than the total cost, it is impossible to complete the circuit.
  • If it is possible, we can find a valid starting station using a greedy strategy.

We can maintain a running gas balance while traversing the stations once.

Greedy Strategy

  • Iterate over the stations, maintaining a running balance of gas in the tank.
  • If the balance becomes negative at station i, we reset the candidate start station to i + 1 and reset the tank balance to 0.
  • Intuition: if you cannot reach station i+1 from station i, then no station between the previous start and i can be a valid starting point.

Keep track of:

  • G: total net gas gain (sum of gas[i] − cost[i])
  • T: current tank balance along the path
  • s: candidate starting index

If the total gain G is negative, we return \(-1\). Otherwise, the final candidate start index s is valid.


1: G ← 0 ▷ Total gas gain
2: T ← 0 ▷ Tank balance
3: s ← 0 ▷ Starting index
4: for i ← 1 to n do
5:     d ← gas[i] − cost[i]
6:     G ← G + d
7:     T ← T + d
8:     if T < 0 then
10:         s ← i + 1
11:         T ← 0
12:    end if
13: end for
14: if G < 0 then
15:     return −1
16: else
17:     return s
18: end if
  • The algorithm performs a single pass through the gas and cost arrays.
  • Running time: \(O(n)\)

SOLUTION 3

Average-Keys

  • Use any tree traversal (for example, post-order) starting at x.
  • Recursively compute, for each subtree:
    • The number of nodes in the subtree.
    • The sum of the keys in the subtree.
  • At the root x, compute average = sum / count.

Running time: \(O(n)\) since each node is visited once and the work per node is \(O(1)\).

Average-Keys(x)
1: if x == null then
2:   return 0
3: else
4:   (count, sum) ← Count-Sum(x)
5:   return sum/count
6: end if
Count-Sum(x)
1: if x == null then
2:   return (0, 0)
3: else
4:   (leftcount, leftsum) ← Count-Sum(x.left)
5:   (rightcount, rightsum) ← Count-Sum(x.right)
6:   count ← leftcount + rightcount + 1
7:   sum ← leftsum + rightsum + x.key
8:   return (count, sum)
9: end if

Kth Smallest Element

  • A BST stores values in sorted order by key.
  • In-order traversal (Left, Root, Right) visits nodes in ascending key order.
  • Maintain a counter during traversal; when it reaches k, return the corresponding node.

Time complexity: In the worst case, we may visit all nodes, so \(O(n)\).


    SmallestElement(T, k):
        count ← 0
        result ← null
        return Inorder(T)
  
Inorder(x):
    if x = null or result ̸= null then
        return
    end if
    Inorder(x.left)
    count ← count + 1
    if count = k then
        result ← x
         return
    end if
    Inorder(x.right)

Range-Search

There is an easy \(\Theta(n)\) solution, but we want an algorithm that runs in time \(O(k + h)\) where:

  • k is the number of reported nodes (in the range).
  • h is the height of the search tree.

Use the BST ordering property to avoid unnecessary work:

  • Only visit subtrees that could contain keys in \([a, b]\).
  • If the current node's key is in \([a, b]\), add it to the result.
  • If the current key is greater than a, explore the left subtree.
  • If the current key is less than b, explore the right subtree.

This prunes entire subtrees whose keys all lie outside the range.

  • The algorithm avoids traversing subtrees that do not intersect \([a, b]\).
  • Each reported node contributes to the k term.
  • Each root-to-leaf search path has length at most h, and we may traverse at most two such paths at each boundary.
  • Total running time: \(O(k + h)\)
Range-Search(x, a, b):
    if x == null then
        return [ ]
    end if
    if x.key > b then
        return Range-Search(x.left, a, b)
    end if
    if a ≤ x.key ≤ b then
        results ← Range-Search(x.left, a, b)
        results.append(x)
        results.extend(Range-Search(x.right, a, b))
        return results
    end if
    if x.key < a then
        return Range-Search(x.right, a, b)
    end if

EXTRA SOLUTION

  • Setting z to black would indeed not violate property 4 (red nodes must have black children), since z has no children yet.
  • However, it would violate property 5, which requires all paths from any node to its descendant leaves to contain the same number of black nodes.
  • Inserting z as a black node increases the black-height of every path that passes through z by 1.
  • Other paths in the tree that do not pass through z remain unchanged, creating an imbalance in black-heights.
  • To preserve property 5, z is inserted as a red node, which does not change the black-height of any path.
  • Any violations of property 4 arising from a red parent and red child can then be fixed using local rotations and recoloring.
