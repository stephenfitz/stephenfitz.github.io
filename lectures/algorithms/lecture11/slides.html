COUNTING SORT

Non-comparison sort for integer keys \(A[1..n]\subseteq\{1,\dots,k\}\).

  • Auxiliary arrays: output \(B[1..n]\), counts \(C[1..k]\)
  • Stable when filled from right to left
  1. Initialize counts \(C[i] \leftarrow 0\)
  2. Count occurrences: \(C[A[j]] \leftarrow C[A[j]]+1\)
  3. Prefix sums: \(C[i] \leftarrow C[i]+C[i-1]\)
  4. Place items (stable) into \(B\) scanning \(A\) right-to-left

COUNTING-SORT(A[1..n], k)
  let B[1..n], C[1..k]
  for i ← 1..k: C[i] ← 0
  for j ← 1..n: C[A[j]] ← C[A[j]] + 1
  for i ← 2..k: C[i] ← C[i] + C[i-1]
  for j ← n..1: 
    B[C[A[j]]] ← A[j]
    C[A[j]] ← C[A[j]] - 1
  return B
  • Time: \(\Theta(n + k)\); Space: \(\Theta(n + k)\)
  • If \(k=O(n)\), then linear time
  • Stable (preserves order among equal keys)

RADIX SORT

  • Historical origin: Hollerith’s 1890 census tabulation
  • Digit-by-digit sort with a stable inner sort
  • Use LSD-first (least significant digit first) for correctness

Stable sort by digit \(t=1,2,\dots,d\) yields global order.


RADIX-SORT(A, d, k) # d digits, each in 0..k−1
  for t ← 1..d:
    A ← STABLE-COUNTING-SORT-BY-DIGIT(A, t, k)
  return A

\(\Theta(d(n+k))\)

QUICK SELECTION

ORDER STATISTICS

  • Select the ith smallest of n elements (the element with rank i).
  • Special cases: minimum (i=1), maximum (i=n), median \(\lfloor (n+1)/2 \rfloor\) or \(\lceil (n+1)/2 \rceil\).

NAIVE ALGORITHM: SORT THEN INDEX

  • Sort the array; return element at position i.
  • Running time: \(\Theta(n \log n)\) to sort + \(\Theta(1)\) to index → \(\Theta(n \log n)\).
  • Sorting unnecessarily solves a harder problem than selection.

RANKING VS. SORTING

  • An element has rank i if exactly i elements are \(\le\) it.
  • We can select by ranking without fully sorting.
  • This motivates a divide-and-conquer selection algorithm.

DIVIDE-CONQUER-COMBINE (QUICKSELECT)

  1. Divide: Partition around pivot x so that lower part \(\le x\) and upper part \(\ge x\).
  2. Conquer: Compute rank of x; recurse only into the part that can contain the answer.
  3. Combine: Trivial.

Partition step: elements on the left are \(\le x\), on the right are \(\ge x\).

We recur only on one side after checking the pivot's rank.

RANDOMIZATION

  • Choose pivot at random (or randomize the array); expected good splits.
  • Ensures \(\mathbb{E}[T(n)] = \Theta(n)\) even though worst case is quadratic.

RAND-SELECT Pseudocode


# returns the i-th smallest element in A[p..q]
RAND-SELECT(A, p, q, i) 
  if p = q:
    return A[p]
  r ← RAND-PARTITION(A, p, q)
  k ← r - p + 1 # rank of A[r] within A[p..q]
  if i = k:
    return A[r]
  elif i < k:
    return RAND-SELECT(A, p, r-1, i)
  else:
    return RAND-SELECT(A, r+1, q, i - k)

complexity

  • Lucky split: Each step shrinks by a constant factor (e.g., 9/10).
  • Unlucky split: Pivot is extreme; subproblem size drops by 1.
  • Partition work per level is linear in subproblem size.

Recurrence Scenarios

  • Good case: \(T(n) = T(\tfrac{9}{10}n) + \Theta(n) = \Theta(n)\).
  • Worst case: \(T(n) = T(n-1) + \Theta(n) = \Theta(n^2)\) (arithmetic series).
  • Expected: With random pivots, \(\mathbb{E}[T(n)] = \Theta(n)\).

SUMMARY

  • Selection can be done faster than sorting: linear expected time.
  • Key ideas: partitioning, rank comparison, single-branch recursion.
  • Randomization yields robust expected performance.
