QUESTION 1

Job Scheduling with Deadlines

You are given a list of n jobs, where each job i has:

  • A deadline \( d_i \)
  • A profit \( p_i \)

Each job takes exactly 1 unit of time to complete. Only one job can be scheduled at a time, and a job must be completed on or before its deadline to earn its profit.

The task is to schedule the jobs in such a way that the total profit is maximized.

  • Input:
    • An array of n jobs, where each job has:
      • A deadline \( d_i \) (positive integer)
      • A profit \( p_i \) (non-negative integer)
  • Output:
    • A list of selected jobs (or their indices) that yields the maximum total profit.

QUESTION 2

Gas Station Problem

You are driving around a circular route with n gas stations. Each station i provides:

  • gas[i]: the amount of gas available at station \( i \)
  • cost[i]: the amount of gas required to travel from station \( i \) to station \( (i + 1) \bmod n \)

Your car has an unlimited gas tank (but starts empty), and you can start at any station. You need to find the starting gas station index from which you can complete the circuit exactly once without running out of gas.

If it is not possible to complete the circuit, you should return \(-1\).

  • Input:
    • Two arrays of length n:
      • \(\text{gas}[1 \dots n]\): amount of gas at each station
      • \(\text{cost}[1 \dots n]\): gas needed to travel to the next station
  • Output:
    • An integer representing the index of the starting gas station.
    • Return \(-1\) if the journey is impossible.

Input:

\(\text{gas} = [1, 2, 3, 4, 5]\)

\(\text{cost} = [3, 4, 5, 1, 2]\)

Output: \(3\)

Explanation: Start at station 3, then go to stations 4 → 0 → 1 → 2 → back to 3, and you never run out of gas.

QUESTION 3

Operations on a Binary Search Tree

Design algorithms for implementing the following operations on a binary search tree (BST):

  1. Average-Keys
  2. Kth Smallest Element
  3. Range-Search

Each part specifies its own running-time requirement and hints.

Average-Keys

Task: Given a node \( x \), return the average value of the keys in the subtree rooted at \( x \).

For full credit, your procedure should run in time \( O(n) \), where \( n \) is the number of nodes in the subtree.

Hint: Separately compute:

  • The number of nodes in the subtree.
  • The sum of the keys in the subtree.

Then compute the average as \(\text{sum} / \text{count}\).

Kth Smallest Element

Task: Given a BST \( T \) and a positive integer \( k \), find the \( k \)-th smallest element in the BST.

Hint: Perform an in-order traversal of the BST and keep a counter of how many nodes have been visited. The in-order traversal of a BST visits the keys in sorted order.

Range-Search

Task: Given an interval \([a, b]\) and a tree \( T \), return a list of all the nodes with keys in the range \([a, b]\).

There is an easy \( \Theta(n) \) solution that visits every node, but for credit your algorithm should run in time \( O(k + h) \), where:

  • \( k \) is the number of nodes in the range \([a, b]\).
  • \( h \) is the height of the search tree.

EXTRA QUESTION

Red-Black Tree Insertion

A red-black tree is a binary search tree that satisfies a set of structural properties designed to keep the tree balanced.

Consider the behavior of the standard insertion procedure RB-Insert for red-black trees.

A red-black tree satisfies the following properties:

  1. Every node is either red or black.
  2. The root is black.
  3. Every leaf (NIL) is black.
  4. If a node is red, then both its children are black.
  5. For each node, all simple paths from the node to descendant leaves contain the same number of black nodes.

The procedure RB-Insert sets the color of the newly inserted node \( z \) to red.

If instead the color of \( z \) were set to black, property 4 of a red-black tree (that a red node cannot have red children) would not be violated.

Question: Why not set the color of \( z \) to black during insertion?
