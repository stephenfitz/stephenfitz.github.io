SOLUTION 1

  • Maintain a visited set to record nodes that have already been explored.
  • For each node from 1 to n:
    • If it has not been visited, start a BFS from that node.
    • The BFS visits all nodes in that connected component.
    • Each time a new BFS starts, we have discovered a new connected component.
  • Increment the component count each time a new BFS is started.

Running time: BFS on the whole graph runs in \(O(n + m)\), where n is the number of nodes and m is the number of edges.


Build adjacency list G[1 . . . n] from edges
Initialize empty set visited
Initialize count ← 0


function BFS(u):
    Initialize queue Q ← [u]
    while Q is not empty do
        v ← Q.pop()
        for each neighbor w of v in G[v] do
            if w /∈ visited then
                Add w to visited
                Enqueue w into Q

for u ← 1 to n do
    if u /∈ visited then
        Add u to visited
        BFS(u)
        count ← count + 1

SOLUTION 2

  • Use DFS with a coloring scheme for each vertex:
    • White: unvisited.
    • Gray: currently in the recursion stack (in progress).
    • Black: finished.
  • When exploring an edge from node u to neighbor v:
    • If v is white, recursively continue DFS on v.
    • If v is gray and v is not the parent of u, then a cycle has been detected.

Running time: A single DFS traversal explores all vertices and edges in \(O(n + m)\).

HasCycle(n, G):
  Initialize color array color[1 . . . n] ← White
  for u ← 1 to n do:
    if color[u] is White then
        if DFS(u, −1) returns true then
            return true
  return false
function DFS(u, parent):
  color[u] ← Gray
  for each neighbor v of u in G[u] do
    if color[v] is White then
        if DFS(v, u) returns true then
            return true
    else if color[v] is Gray and v ≠ parent then
  return true

SOLUTION 3

Hint: This is a variant of a single-source shortest path problem with a constraint on the number of stops. It can be approached using a modified Dijkstra algorithm or a layered Bellman–Ford algorithm.

Key idea (modified Dijkstra):

  • Maintain a min-priority queue of tuples (cost, current node, remaining stops).
  • At each step, expand the state with the smallest current cost.
  • Decrease the remaining stop count as you move along edges.
  • Only push a neighbor into the queue if the number of remaining stops is non-negative.
  • If you reach the destination with stops remaining ≥ 0, return the current cost.

Time complexity:

  • Let n be the number of cities and m the number of flights.
  • Each node can be inserted into the priority queue up to K times.
  • Total complexity is \(O(K \cdot m \cdot \log n)\).
CheapestFlightWithKStops(n, flights, src, dst, K)
  Build adjacency list G from flights
  Initialize min-priority queue Q
  Enqueue (0, src, K + 1) into Q
  while Q is not empty do
    (cost, u, stops) ← Q.pop()
    if u = dst then
      return cost
    if stops > 0 then
      for each neighbor (v, w) of u in G do
        Enqueue (cost + w, v, stops − 1) into Q
  return −1

EXTRA SOLUTION

Hint: This problem reduces to detecting a cycle in a directed graph.

  • Treat each course as a node in a directed graph.
  • For each prerequisite pair [a, b], add a directed edge b → a.
  • If the directed graph contains a cycle, then it is impossible to finish all courses.
  • Use DFS with three states for each node:
    • 0: unvisited,
    • 1: visiting,
    • 2: finished.
  • Encountering a node in the visiting state during DFS indicates a cycle.
CanFinishCourses(n, prerequisites):
  Build adjacency list G[0 . . . n−1]
  Initialize visited[0 . . . n−1] ← 0
  ▷ 0 = unvisited, 1 = visiting, 2 = finished
  for u ← 0 to n−1 do
    if visited[u] = 0 then
      if not DFS(u) then
        return false
  return true

function DFS(u):
  if visited[u] = 1 then
    return false
  else if visited[u] = 2 then
    return true
  visited[u] ← 1
  for each neighbor v in G[u] do
    if not DFS(v) then
      return false
  visited[u] ← 2
  return true
  • Building the graph: \(O(n + m)\), where n is the number of courses and m is the number of prerequisite pairs.
  • DFS traversal: Each node and edge is visited at most once, so DFS runs in \(O(n + m)\).
  • Total complexity: \(O(n + m)\).
