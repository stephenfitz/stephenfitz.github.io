# Authoring guide for the course decks

This guide explains how the decks are built and edited, and the editorial standards the courses follow. The rendered reference for every layout is `curriculum/layout_reference/slides.pdf` (source: `curriculum/layout_reference/slides.md`); open both.

## 1. Quality bar

These are full-day, production-quality courses for technical professionals in the energy industry (engineers, geoscientists, data analysts who can read Python and basic algebra).

- **One idea per slide.** The title states the idea as a sentence-case assertion ("Scaling must happen inside each fold"), not a topic label ("Scaling").
- **Show, don't list.** Every concept that can be drawn or plotted should be. Target: at least half of all content slides carry a figure or diagram; most of the rest use a structured layout (cards, compare, steps, stats, table, code, equation). Plain bullet-only slides should be under 20% of the deck.
- **Correct before clever.** Every number on a slide is computed or checked in Python. Every plot is generated by code in `curriculum/figs/`. Synthetic data is labelled as synthetic in the caption. Do not invent statistics, benchmark results, citations, dates or quotations; if unsure, leave it out or state it qualitatively.
- **Teach, then check.** Each 10–15 minutes of explanation ends in a question, a worked example, or a short exercise with a worked answer in the notes.
- **Energy context.** Use oil and gas and wider energy examples (well logs, facies, drilling, production, ESPs, seismic, pipelines, wind/solar/load forecasting). Do not claim field performance from teaching examples.
- **Consistent terminology** across modules: training / validation / test; fold; baseline; leakage; prediction contract; event vs row; logits.

## 2. Files and commands

| What | Where |
|---|---|
| Slide source | `<course>/<module>/slides.md` |
| Module figures | `curriculum/figs/<key>.py` (keys: ml1–ml5, nn1–nn5). New figure names must start with `<key>_`. |
| Shared figures | `curriculum/figs/core.py` — names without a prefix, e.g. `knn_boundaries` |
| Figure toolkit | `curriculum/figlib.py` (style, sizes, diagram primitives) |
| Outputs | `slides.pdf`, `slides.html`, `slides.pptx`, `instructor_notes.pdf`, `instructor_notes.md` next to `slides.md` |

```bash
python3 curriculum/make_figures.py --only ml3                 # all ml3 figures
python3 curriculum/make_figures.py --only ml3 --match kmeans  # just matching functions
python3 curriculum/build.py machine_learning_course/Module_3_Unsupervised_Learning_1/slides.md
python3 curriculum/build.py --pdf-only <slides.md>            # faster while iterating
python3 curriculum/review.py <slides.pdf> <out_dir> --per 9    # contact sheets to inspect
python3 curriculum/build.py --no-pptx <slides.md>              # full build without the PowerPoint copy
python3 curriculum/verify.py                                    # package-wide checks
python3 curriculum/check_html.py                                # browser checks (needs Playwright)
python3 curriculum/check_figures.py --only ml3                  # scan figures for hidden, clipped or colliding elements
```

Builds are deterministic: figures, PDFs, HTML and PPTX files are byte-identical when rebuilt from unchanged sources (fixed seeds, fixed metadata dates, no random ids). If a rebuild changes a file you did not touch, something is not seeded.

The HTML deck embeds every slide as inline SVG. A slide whose SVG would exceed about 1.2 MB (dense scatter plots) is embedded as a 2880 × 1620 image instead, so the offline deck stays fast; the PDF is always fully vector. The PowerPoint file is a presentation copy (one image per slide, with notes, titles, alt text and sections); never edit it — edit `slides.md`.

The engine (`render.py`, `build.py`, `markup.py`, `figlib.py`, `theme.py`) and the shared figures (`figs/core.py`) affect every module: after changing them, regenerate the figures, rebuild all decks and review them. For a module-specific variant of a shared figure, add a prefixed copy to that module's figure file.

## 3. Slide syntax

Slides are separated by a line containing only `---`. Every slide needs a title and a `:::notes` block.

```text
## Title as an assertion                 (content slide; '# Title' = cover or section)
@type concept|section|exercise|debrief|lab|reference|recap|objectives|agenda|statement
@layout auto|split|split-left|figure|pair|cards|compare|steps|steps-vertical|stats|table|code|code-split
@figure name            repeatable; two figures + @layout pair (or figure) = side by side
@caption text           under the figure (provenance: computed / schematic / course data)
@equation latex         repeatable; rendered as display math in a panel
@callout text           key-idea box anchored at the bottom (blue)
@warning text           caution box anchored at the bottom (orange)
@stat value | label | color     repeatable, 1–4 tiles (color: blue teal orange purple red gold)
@time 4 min   @mode Pairs       chips on exercise / lab slides
@notebook path          lab slides: exercises/... path relative to the module folder (repeatable)
@deliverable text       lab slides: evidence to submit (repeatable)
@section text           override the small kicker above the title
@figwidth 0.5           split layouts: fraction of width given to the figure (default 0.56)
@cols 2                 cards: force the number of columns
@highlight 3-5,8        code: highlight lines
@source url ; url       reference shown in the notes
@label / @meta / @footer        cover slide only
### Card heading {tag}  starts a card (tags: good bad warn blue teal orange purple red gold ink)
- bullet                (two-space indent '  - ' for a sub-bullet)
1. numbered item        (steps layouts: '1. **Title** — description')
plain line = paragraph
| table | rows |        first row is the header
```code fences```       language after the fence; a block tagged `output` renders as a console panel
:::notes ... :::        instructor notes (plain text; blank line = new paragraph)
```

Inline markup: `**bold**`, `*italic*`, `` `code` ``, `==accent==` (blue emphasis for a key term), `$inline math$` (subset of LaTeX: sub/superscripts, Greek, \frac, \sqrt, \hat, \sum, \log …). Write `\$` for a literal dollar sign.

### Slide types

| Type | Use | Notes |
|---|---|---|
| cover | First slide | `@label Machine Learning / Module 3`, subtitle line, 2–4 `@meta` chips |
| agenda | Slide 2: the day plan | table `| 09:00 | Session | Kind |`; kinds: Lecture, Lab, Exercise, Discussion, Break, Lunch |
| objectives | Learning outcomes | 4–6 numbered outcomes, each an observable skill |
| section | Divider for each part (5–7 per day) | subtitle line + 3–5 bullets "in this part"; numbered automatically |
| concept | Default teaching slide | any layout |
| exercise | Question for learners, answer in notes | `@time`, `@mode`; bullets become numbered questions |
| debrief | Discussion/answers after an exercise or lab | |
| lab | Hands-on block | tasks as bullets, `@notebook`, `@deliverable`, `@time` |
| recap | Key takeaways at the end of a part or day | 4–6 check-marked statements |
| statement | One big idea, centered | use sparingly (≤ 3 per deck) |
| reference | Further study | real, verifiable references only |

### Layouts and capacity

The engine shrinks text to fit and refuses to build if content still overflows. Stay well inside these limits so text stays large:

| Layout | Good for | Comfortable content |
|---|---|---|
| bullets (default) | short arguments | 3–5 bullets, ≤ 2 lines each (≈ 110 characters) |
| split / split-left | explanation beside a figure | 2–4 bullets of ≤ 90 characters, optional equation and callout; figure drawn at HALF size |
| figure | a figure that needs the full width | 0–2 lead lines, caption ≤ 2 lines; figure drawn at FULL or WIDE size |
| pair | two related figures | each figure drawn at HALF size |
| cards / compare | 2–6 parallel ideas | card: heading + 2–3 short bullets |
| steps | a process of 3–6 stages | `1. **Stage** — 3 to 8 words` |
| steps-vertical | 4–7 ordered steps with more words | one line each |
| stats | 1–4 headline numbers | computed numbers only |
| table | comparisons across ≥ 3 attributes | ≤ 6 rows × 4 columns, short cells |
| code / code-split | code learners will type or read | ≤ 16 lines, ≤ 78 characters wide (≤ 58 in code-split) |

Auto layout: cards if `###` cards exist, stats if `@stat`, pair for two figures, split when a figure has 3+ bullets or an equation, figure otherwise, code, table, bullets. Set `@layout` explicitly when you care.

A slide may only contain what its layout shows (the build fails if, say, a table is put on a figure slide).

## 4. Figures

Every figure is a Python function in `curriculum/figs/<key>.py`, decorated with `@fig`, that calls `save(name, f, source, kind)`. `from curriculum.figlib import *` gives you numpy (`np`), matplotlib (`plt`), the palette and all helpers.

```python
@fig
def kmeans_init():
    X, _ = make_blobs(300, centers=4, cluster_std=.8, random_state=4)
    f, axs = half()                      # sized for the right column of a split slide
    ax = axs[0]
    points(ax, X, np.zeros(len(X), int), s=14)
    clean(ax, 'Feature 1', 'Feature 2')
    save('ml3_kmeans_init', f, 'Synthetic blobs, seed 4; k-means++ seeding from scikit-learn.', kind='computed')
```

**Build warnings.** Every figure placed on a slide is measured: the build warns when it is shrunk below 72% of its drawn size, fills less than 55% of its box, or when its smallest text lands below 8 pt on the slide (exponents and subscripts excluded). A clean build has no warnings.

**Glyphs.** IBM Plex lacks a few mathematical symbols (for example ⋮ ∝ ⌊ ⌋ ▼). Figures fall back to DejaVu Sans automatically; on slides, the renderer routes missing glyphs to DejaVu as well. Prefer words or mathtext for rare symbols.

**Sizes (inches, drawn at ~1:1 on the slide).** `FULL = (11.8, 4.3)`, `WIDE = (11.8, 3.6)`, `HALF = (6.3, 4.9)`, `SQUARE = (5.6, 5.0)`. Use `sub(n)` for a row of plots at full width, `half(n)` for the split column, `canvas(w, h)` for diagrams. Match the figure to the layout: HALF for split/pair, FULL/WIDE for figure. The build warns when a figure is shrunk below 72% or fills less than 55% of its box — fix every such warning.

**Style rules.**
- Text in figures ≥ 12 pt (tick labels 12, labels 14, diagram labels 13–16). Never below 11.
- Palette from `theme.py`: BLUE primary, ORANGE contrast, TEAL third; PURPLE, RED, GOLD sparingly. Class 0/1 = BLUE/ORANGE everywhere.
- Label lines directly (`endlabel`) rather than with a legend when there are ≤ 4 series. Axis labels in sentence case with units.
- No figure titles that repeat the slide title; panel titles only for multi-panel figures.
- Keep backgrounds white, grids light, spines left/bottom only (the defaults do this).
- Diagrams: rounded boxes (`box`), arrows (`arrow`, `elbow`), flows (`flow`), layered networks (`network`), numeric grids (`matrix`), tensor blocks (`block3d`), chips/labels (`chip`, `label`), braces (`bracket`, `vbracket`), icons (`check`, `cross`), covariance ellipses (`gaussian_blob`). Canvas coordinates are inches. Use tint fills with coloured borders for ordinary boxes; solid fills for the one element that matters most.
- Colour means something: the same concept keeps the same colour throughout a deck (e.g. training = BLUE, validation = TEAL, test = ORANGE; data = grey, model = BLUE, output = ORANGE).

**Provenance.** `save(..., source=..., kind=...)` with kind `computed` (from code/data/exact formula), `schematic` (conceptual drawing), or `data` (supplied course dataset). The slide caption must say the same thing in plain words ("Synthetic example, seed 3", "Schematic", "Computed from esp_train.csv"). Schematic curves must never look like measurements without saying so.

**Reproducibility.** Fix random seeds. Figures must not download anything. Heavy computations should take seconds, not minutes (subsample).

## 5. Structure of a teaching day

A day runs 09:00–17:00: about 3.5 h of taught content, 2.5 h of labs, breaks and lunch. The deck mirrors it:

1. Cover → agenda (times match the parts) → learning outcomes → a warm-up question or motivating energy case.
2. 5–7 parts, each opened by a section slide, each 30–60 minutes of teaching, each ending with an exercise, a check question or a recap.
3. Two or three lab blocks placed where they belong in the day (not all at the end), each with a lab slide (tasks, notebook, evidence, time) and a debrief slide afterwards.
4. Close: key takeaways (recap) → exit check (exercise) → references.

Pace: roughly 2–3 minutes per content slide, 3–5 minutes per exercise. A full day is ~85–100 slides (capstone day ~60–75).

## 6. Writing

- Titles: ≤ 60 characters, sentence case, an assertion. No trailing period. No two slides with the same title in a module.
- Bullets: ≤ 5 per slide, parallel grammar, no full stops needed for fragments (be consistent within a slide). Prefer concrete nouns and numbers.
- Define every symbol the first time it appears (on the slide or in the notes).
- Use `==term==` for the one term the slide introduces.
- Spelling: Oxford convention, i.e. British spellings with -ize (colour, centre, neighbour, behaviour, modelling, labelled, grey, analyse; standardize, normalize, optimize, regularization). Code identifiers keep their library spelling.
- Code must run as written given the stated context (imports shown or obviously implied). Use current library APIs (scikit-learn ≥ 1.5, PyTorch ≥ 2.2).

## 7. Instructor notes

Every slide has notes (60–200 words; more for exercises and labs). Include what to say (the explanation in full sentences), a question to ask the room, the answer to every exercise with the arithmetic, common misconceptions, and a transition to the next slide. Put timing cues in brackets, e.g. "[3 min]". Cite primary sources with `@source` (documentation pages, papers) — only real ones you are certain of.

## 8. Quality-assurance checklist

1. `make_figures.py --only <key>` runs cleanly; open every new PNG in `curriculum/figures/` at full size and look at it (edges, arrows and labels all drawn; nothing overlapping or cut off). Run `check_figures.py --only <key>` and inspect every finding.
2. `build.py <slides.md>` builds with no errors and no figure-size warnings.
3. `review.py` contact sheets: look at every slide. Check for sparse slides (add a figure or restructure), crowded slides (split them), small figure text, colours without meaning, inconsistent terminology.
4. Recompute every number shown on slides or in notes.
5. Agenda times match the sections and labs; lab slides point at notebooks that exist.
